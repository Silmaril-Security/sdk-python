# Governance identity contract 1.0.0

This directory is the authoritative cross-language contract. Its SHA256SUMS pins exact bytes; consumers vendor these files unchanged and test the digest and vectors. A released immutable archive is published only after review through the existing release path.

## Identity and request authority
Concrete resource refs are {kind,id,parent_id?}; kind is agent/tool/mcp_server/mcp_tool/plugin/skill/extension. id is a nonempty exact configured/catalog identity, case sensitive, never display text or an installation/row ID. Only mcp_tool has parent_id and it is required/nonempty. Policy selectors have the same shape but may omit id for wildcard. No connector/endpoint governance kinds.
Single requests add optional resource and identity_revision. Batches add optional resources (exactly one nullable ref per text, preserving order) and identity_revision (one immutable resolver snapshot). Reject ambiguous resource plus resources and bad lengths. Retain raw tool_name/tool_names for ML and audit. Metadata never supplies identity, agent binding or authenticated principal. MCP aliases resolve in the adapter from the actual configured dispatch catalog, using exact configured identity first and a unique host alias mapping second; never guess by globally replacing underscores with hyphens. Unknown/colliding dispatch names are invariant failures.
A runtime/schema capability must be established before new clients send these fields to legacy services. Readers are deployed first. Resource ids alone are assertions of the authenticated adapter, not new authentication. Do not let resource.kind=agent alter server-controlled agent bindings.

## Versioning and activation
Runtime schemas 1-5 retain existing matching and request inference behavior. Schema 6 explicitly activates this contract; it requires governance.resolution when governance exists. No automatic persisted schema upgrade. Projection schema 1 remains for legacy runtime policies; schema 2 is emitted for active schema 6 and requires consumers implementing this contract. Inventory report schemaVersion 2 adds governanceResource on governed items and governanceCapabilities on the report. Preserve v1 readers. Capabilities report contract_version=1.0.0, identity_revision, supported resource_kinds and actual installed enforcement components; do not derive readiness from inventory existence alone.
Old clients must not be reported protected by schema 6. Activation checks all consumers in the policy scope, does not silently narrow scope, and refuses missing/stale capabilities. No API call may unconditionally migrate a policy during ordinary save/read.

## Matching
An absent selector matches every context. A typed selector never matches a missing resource. Same-kind matching is exact for present selector id and parent_id. The sole cross-kind match is mcp_server -> mcp_tool, comparing selector.id to actual.parent_id; omitted server id matches tools under every resolved server. An exact mcp_tool selector matches only id+parent_id. No other inheritance.
Ordered resolution is first matching rule, default allow. Specificity is a descending lexicographic tuple [subject,resource,agent,hook]. Subject: all=0, group=1, principal=2. Resource: absent=0; kind wildcard=1; exact id=2; mcp_tool with parent and wildcard id=2; exact mcp_tool=3. Agent/hook present=1, absent=0. Same-action ties choose lexicographically smallest rule id (Unicode code-point order for cross-language consistency). Equal-score opposite-action rules with intersecting subject/resource/agent/hook scopes are invalid. MCP server/tool scopes intersect through parent identity; exact server and all-tools-under-that-server conflict at equal other specificity. Projection filters authenticated subjects and sorts by authoritative specificity, retaining winning rule IDs; local evaluators consume that ordered projection.

## Failures and evidence
Adapters resolve MCP identity before classify/dispatch. If missing/ambiguous, prevent the affected call in Block mode and record identity_unresolved; Shadow/Warn retain established mode semantics and report incomplete protection. Runtime schema 6 must not fall back from a recognizable MCP tool name to native Tool: absent canonical MCP identity produces governance block with reason=identity_unresolved (mode controls native enforcement). Invalid provided resource shape is a request validation error. Explicit canonical resource is authoritative over raw display spelling; classify behavior still uses raw tool_name.
Governance response retains action,rule_id?,policy_version and adds resource?,identity_revision?,reason? (identity_unresolved only for identity failures). Receipts read nested governance.policy_version and retain actual policy action/native response plus canonical resource and identity_revision. Classification BENIGN must not erase a governance block. Explicit caller Shadow/Warn is never strengthened by an older/stronger backend mode.

## Artifact and rollout
Readers -> SDKs -> standalone plugins -> managed adapters/native app -> installed/loaded verification -> schema activation -> observed denial. Pin exact versions/digests. Build final macOS bundle only after qualified plugin/adapter versions; standalone packages do not replace its native runtime. Preserve unrelated AppConfig fields and existing policy IDs/scopes/resolution. Rollback restores a compatible policy/runtime pair. Configured/applied/observed are distinct.

## Capability wire shape (readiness is independent of activation)
/governance/policy adds optional capabilities: {contract_versions:["1.0.0"],runtime_schema_versions:[6],resource_identity:true}. It advertises reader support even while returning projection schema1; active schema alone MUST NOT be used as readiness or this creates an activation deadlock. Schema2 also includes contract_version:"1.0.0".
Inventory report governanceCapabilities has {contract_version:"1.0.0",identity_revision:string,resource_kinds:[kind],components:[{id:string,version:string,contract_version:"1.0.0",identity_revision:string,verified_at:ISO8601,expires_at:ISO8601}]}. Component IDs identify actual installed runtime/Guardian/host adapters. A component is ready only if loaded executable/adapter digest/version matches the expected bundle, snapshot revision matches, and verified_at <= now < expires_at; the backend additionally caps proof age at 15 minutes and rejects future verification times. Missing evidence is incompatible. Every applicable consumer in the authoritative scope roster must be represented; no empty list succeeds. Emitting resource refs is distinct from claiming enforcement readiness. Capabilities may be absent while readers/identity support is deployed. Do not fabricate positive component evidence to unblock activation.
